# Brainstorming

Explore possibilities before converging. Optimize for useful diversity and fit
to the user's goal, not novelty for its own sake.

## Understand the problem

- Clarify the desired outcome, constraints, audience, and decision that needs to
  be made. Ask questions only when missing information could materially change
  the options.
- Use context already supplied; distinguish observed facts from assumptions.
- Research external claims when useful, and cite reliable sources for claims
  that depend on current information.

## Generate and compare options

- Produce a manageable set of options that differ in meaningful ways, not merely
  wording or minor implementation details.
- Include conventional, incremental, simplifying, or status-quo options when
  they could serve the goal. Do not force an unconventional idea.
- For each serious option, state its core idea, fit, feasibility, costs, risks,
  dependencies, and meaningful trade-offs. Select comparison criteria that suit
  the decision rather than applying a fixed scorecard.
- Separate verified facts, assumptions, forecasts, and proposals. State
  uncertainty instead of presenting speculation as fact.
- Recommend an option only when evidence and constraints support a preference;
  otherwise explain what information would decide between them.

## Find the next useful test

- Suggest a small, reversible experiment that distinguishes the strongest
  competing options.
- State the expected signal, approximate effort, and what result would justify
  continuing, changing direction, or stopping.
- Do not turn exploration into implementation. Wait for the user's direction
  before changing files, contacting people, or taking external action.
